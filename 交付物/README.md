# 交付物

> **由 `文档/` 下的 md 生成的对外文档 —— 这里是「产物区」，不要直接编辑。**

## 三份定位独立的文档

| 文件 | 内容 | 生成方式 |
|---|---|---|
| `亏了-规则文件.docx` | **只讲规则与参数** —— 状态流转、取值表、判定口径（**写代码时查这本**） | `python ../工具/_md2docx.py 亏了-规则文件.docx spec` |
| `亏了-设计解释.docx` | **只讲为什么** —— 好处、坏处、取舍、放弃的方案（**做决策时查这本**） | `python ../工具/_md2docx.py 亏了-设计解释.docx design` |
| `亏了-页面与交互规格.docx` | **页面怎么摆、怎么交互、文案怎么写** —— 布局、组件、块序、尺寸（**做样式、走查时查这本**） | `python ../工具/_md2docx.py 亏了-页面与交互规格.docx layout` |
| `亏了-需求规格与设计说明.docx` | 以上三份的**合订本**（对外评审用） | `python ../工具/_md2docx.py 亏了-需求规格与设计说明.docx all` |
| `参数速查表.docx` | 全部数值的紧凑速查表（107 张表，双栏排版） | `python ../工具/build_param_tables.py` |

## 三份之间怎么跳

```
亏了-规则文件.docx          亏了-设计解释.docx        亏了-页面与交互规格.docx
   R 规则与参数      ←→        D 为什么这么设计    ←→     L 界面怎么摆
        │                              │                        │
        └──────── 双向指针 ────────────┴────────────────────────┘
```

- 规则文件里，界面相关的章节留**编号占位**，指到界面文件（L 编号）
- 界面文件里，每条规格都标**它受哪条规则约束**（R 编号）
- 设计解释里，每个 D 小节标注**对应的规则章节**（R 编号）

## 改内容改哪边

```
文档/需求规格.md              ──( _md2docx.py ... spec )──>  交付物/亏了-规则文件.docx
文档/设计说明.md              ──( _md2docx.py ... design )──> 交付物/亏了-设计解释.docx
文档/页面布局与交互规格.md      ──( _md2docx.py ... layout )──> 交付物/亏了-页面与交互规格.docx
文档/参数速查表.md            ──( build_param_tables.py )──> 交付物/参数速查表.docx
```

**只改 `文档/` 下的 md，然后重新生成。**

直接改 docx 的话，下次重新生成会被**整个覆盖** —— 改动全部丢失，且不留痕迹。

## 改完必跑

```powershell
cd ../工具
python check_docs.py              # md ↔ docx 的标题数 / 表格数是否一致
python _verify_param_tables.py    # 参数速查表逐格比对
python check_refs.py              # 交叉引用与交付物存在性
cd ../demo/tests && node 跑全部校验.js    # demo 31 个校验脚本
```

> `check_docs.py` 是这次仓库整理留下的守卫 —— **它存在的唯一原因是**：
> 2026-11-21 发现 `需求规格.md` 里多一行代码围栏，docx 因此**少 5 个标题、4 张表**，
> 而 **md 本身渲染完全正常**。没有自动比对，这类问题只能靠人肉发现。
