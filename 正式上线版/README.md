## 🚀 三分钟快速上手（本地跑通）

> 想先看看效果，不上服务器的话。

### 第 1 步：准备数据库

本地装 MySQL 8.0（**不用装 Windows 版，用 Docker 一行搞定**），然后：

```bash
docker run -d --name kuile-mysql -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=root123 \
  -e MYSQL_DATABASE=kuile \
  -e MYSQL_CHARACTER_SET_SERVER=utf8mb4 \
  mysql:8.0
```

或者本地装了 MySQL 的话，直接建库：

```sql
CREATE DATABASE kuile CHARACTER SET utf8mb4;
```

> **💡 为什么是 `utf8mb4` 不是 `utf8`？** MySQL 里的 `utf8` 实际只支持 3 字节字符，
> **存不了 emoji**。昵称里来个 👊 就会报错。`utf8mb4` 才是完整 UTF-8。
>
> **💡 为什么不推荐在 Windows 上装 MySQL？**
> 服务名、字符集、密码策略、卸载残留……Windows 版 MySQL 坑特别多。
> 用 Docker 一行命令搞定，**用完 `docker rm -f kuile-mysql` 卸得干干净净**。
>
> **💡 生产环境用的是「自建 MySQL」，不用 Docker**
> 生产机上直接 `apt install mysql-server`，然后按《上线执行清单》第 4 章配置
> （加固 + 内存调优 + 时区 + 备份）。

### 第 2 步：配置后端

```bash
cd 正式上线版/02-后端
cp .env.example .env
```

编辑 `.env`，至少填这几项：

```ini
NODE_ENV=development
PORT=3000
API_BASE_URL=http://127.0.0.1:3000

DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=kuile
DB_USER=root
DB_PASSWORD=你的密码

# AI 判定先关掉，本地能跑通就行
AI_VERIFY_ENABLED=false

# 内测阶段暂不收取押金（默认值就是 false，一般不用改）
DEPOSIT_ENABLED=false
```

### 第 3 步：装依赖 + 建表 + 启动

```bash
npm install
npm run migrate      # 建表
npm run seed         # 生成演示数据（可选）
npm run dev          # 启动服务
```

看到这行就算成功了：
```
亏了 · 后端服务已启动  port: 3000
```

### 第 4 步：验证

```bash
curl http://127.0.0.1:3000/api/health
```

应该返回 `"db": true`。

### 第 5 步：跑规则测试

```bash
npm test
```
应该看到 `通过 60 项，失败 0 项 ✅`

### 第 6 步：打开小程序

1. 下载[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)
2. 导入目录 `正式上线版/03-小程序前端`
3. 改 `03-小程序前端/config/index.js` 的 `BASE_URL`

> **⚠️ 手机预览时不能用 `127.0.0.1`** —— 那是手机自己，不是你的电脑。
> 查电脑 IP（Windows 命令行）：`ipconfig`，看「IPv4 地址」，
> 填成 `http://192.168.x.x:3000`，手机和电脑要在同一个 WiFi 下。

## 🆕 内测阶段：暂不收取押金

本次上线采用**「内测阶段暂不收取押金」**模式（详细说明见《上线执行清单》第 7.7 节）。

**只改 `.env` 一行：**

```ini
DEPOSIT_ENABLED=false
```

| 环节 | 内测阶段 | 正式收押金 |
|---|---|---|
| 押金档位界面 | **完全不变** | 一样 |
| 点「确认并支付」 | 弹「内测阶段，暂不收取押金」 | 调起微信支付 |
| Flag 是否立成功 | **照样成功** | 支付成功后成功 |
| 记录的押金金额 | **照常记录**（名义押金） | 照常记录 |
| 实际收到的钱 | **0 元** | 按档位金额 |
| 结算失败时 | **不扣押金** | 扣 20%-40% |
| 信用分 | **照常加减** | 照常加减 |

> **💡 为什么要分成「名义押金」和「实收押金」两个数？**
> 因为「承诺」和「到账」是两件事。结算逻辑**只看实收金额** ——
> 这样无论开关什么时候翻转，都不会出现「退一笔从没收到的钱」或「收了钱却不退」。
> 这条铁律由 `tests/beta-deposit.test.js` 的 18 项断言守着。

**打开押金的前置条件**：推送已上线 + 退款已实测到账 + 客服 SLA 已就位。

## 🔐 安全设计要点

| 风险 | 防护措施 | 位置 |
|---|---|---|
| 越权访问 | 所有业务接口校验资源归属 | 各 `routes/*.js` |
| 伪造支付回调 | RSA 验签 + AES-GCM 解密 + 时间戳防重放 | `wechatPay.js` |
| 重复扣款 | 事务 + `FOR UPDATE` + 幂等检查 | `wechatPay.js` |
| 金额篡改 | 全部用「分」整数运算 | `wechatPay.js` |
| SQL 注入 | 全部参数化查询（`?` 占位符） | 全局 |
| 密码泄露 | `.env` 权限 600，不入版本库 | 部署脚本 |
| Token 窃用 | 数据库存储，可随时作废；30 天过期 | `auth.js` |
| 越权查看 | 敏感操作二次校验用户身份 | 各路由 |
| AI 误伤 | 模型故障不判负，转人工复核 | `aiReview.js` |
| 上传滥用 | 类型白名单 + 5MB 限制 | `upload.js` |
| 接口刷量 | Nginx 限流（120 次/分钟/IP） | `nginx-kuile.conf` |
| 🆕 押金资损 | 名义/实收分离，结算只认真收 | `pay.js` + `beta-deposit.test.js` |

## ❓ 常见问题

**Q：为什么不用微信云开发，而要自己买服务器？**
A：押金涉及真实资金流转，必须走你自己的商户号；AI 判定、结算逻辑复杂，自建后端可控性更强。

**Q：能先不开押金上线吗？**
A：**可以，本次上线就是这么做的。** 把 `.env` 的 `DEPOSIT_ENABLED` 保持 `false`，
押金档位照常显示照常选，点「确认并支付」会弹「内测阶段，暂不收取押金」，
Flag 照样立成功。等推送和退款都验证好了再改成 `true` 打开。

**Q：内测阶段用户问「押金什么时候退」怎么办？**
A：回复「内测阶段暂不收取押金，实际没有扣款，因此不需要退款，正式开放时会提前公告」。
**注意：绝不能收下钱。** 内测期收了钱却没有退款通道，等于踩合规红线。

**Q：AI 判错了用户来投诉怎么办？**
A：`ai_review` 表存了每一次判定的原始返回、提示词版本号、耗时。人工复核时能完整还原「当时 AI 怎么判的、为什么」。

**Q：改产品规则要改哪里？**
A：只改 `02-后端/src/domain/rules.js`，然后跑 `npm test`。60 项测试会告诉你有没有改坏。

**Q：前端要写死规则吗？**
A：**绝对不要**。所有周期、押金档位、信用分上限都从 `GET /api/flags/config` 拉。信用分一变，能立的周期立刻跟着变。

**Q：为什么前端不直接看 `depositEnabled` 决定要不要支付？**
A：因为它可能来自**本地缓存**（会过期）。如果服务器把开关从 `false` 改成 `true`，
而缓存没过期，前端会跳过支付，**用户的押金就永远收不到钱了**。
所以前端只管提交，「收不收钱」一律听服务器 `/api/pay/create` 返回的 `beta` 标记。
