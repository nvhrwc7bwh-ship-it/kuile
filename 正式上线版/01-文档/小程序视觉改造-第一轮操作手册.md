## 第 0 章：先搞清楚这次改了什么

### 0.1 一句话总结

**小程序换了一套新皮肤，从绿色变成 demo 的橙色，首页重做了。**

### 0.2 具体动了哪些地方

| 地方 | 改了什么 | 你能看到吗 |
|---|---|---|
| 全局配色 | 品牌色从**绿** `#1F5F4E` 改成**橙** `#FF6B00` | ✅ 很明显 |
| 背景 | 从冷米色改成**暖白** `#FAF7F4` | ✅ 明显 |
| 卡片 | 圆角变大、阴影改成**暖调**（不再是灰黑色） | ✅ 明显 |
| 首页（全新用户） | 新增渐变空态卡 + 靶心图标 + 「立 Flag 会发生什么」三条说明 | ✅ 很明显 |
| 首页（筹备期） | 新增 **24 小时逐秒倒计时** | ✅ 很明显 |
| 首页（进行中） | 新增橙色渐变主卡 + 体重三数 + 进度条 | ✅ 明显 |
| 底部弹窗 / 居中弹窗 / 图标 | 新增三个通用组件，全站复用 | 后续页面才看得到 |
| 广场、通知、我的等 9 个页面 | **本轮没改**，还是老样子 | ❌ 还没变 |

> **💡 为什么首页变了，其它页面没变？**
> 因为整个小程序有 10 个页面。
> 这一轮先把**「地基」**打好 —— 配色、圆角、阴影、按钮、卡片这些公共样式全站统一，
> 再把**首页**做成样板给你看效果。
> 你确认首页的方向对了，下一轮再按同样的方式改剩下 9 个页面。

> **💡 服务器要不要更新？**
> **要。** 本轮改了一个后端文件（给首页的倒计时补了两个字段）。
> 不更新的话，首页倒计时会显示不出来。

### 0.3 这次顺便修了两个 Bug

| Bug | 现象 | 严重程度 |
|---|---|---|
| 立 Flag 页的「选一个周期」列表 | **整块显示不出来**（变量名写错了） | 🔴 高 |
| 首页断卡预警 | 7 天期的用户一进首页就看到「再断 1 次就结束了」，其实是误报 | 🟡 中 |

## 第 1 章：准备工作

### 1.1 你需要开着的东西

| 软件 | 用来干什么 | 在哪打开 |
|---|---|---|
| **PowerShell**（或 CMD） | 敲命令 | 开始菜单搜 "PowerShell" |
| **FinalShell** | 远程操作服务器 | 桌面快捷方式 |
| **微信开发者工具** | 看小程序效果 | 开始菜单搜 "微信开发者工具" |

### 1.2 确认一下你现在在哪个分支

这一步很重要 —— **本轮代码在 `feature/demo-ui` 分支上，还没合并到 `main`**。

> **💡 为什么要用分支？**
> 因为 `main` 分支是「现在能用的版本」。
> 万一新样式有问题，你随时能切回 `main`，网站和小程序立刻恢复正常。
> 等你验收满意了，再把新分支合并进 `main`。

打开 PowerShell，粘贴这一行：

```powershell
cd "e:\9.小程序自己做\02-立了"; & "D:\1、Software\Git\cmd\git.exe" branch
```

**成功标志**：输出里有一行带 `*` 的，意思是「你当前在这个分支上」。

```
  feature/demo-ui   ← 前面有 * 号
* main
```

> **💡 如果看到的是 `* main` 怎么办？**
> 说明你不在新分支上，需要切过去：
> ```powershell
> cd "e:\9.小程序自己做\02-立了"; & "D:\1、Software\Git\cmd\git.exe" checkout feature/demo-ui
> ```

### 1.3 本地先验证一遍（可选，但推荐）

在推送之前，先确认代码本身没问题：

```powershell
cd "e:\9.小程序自己做\02-立了"; node tools/verify.js
```

**成功标志**（最后一行）：

```
✅ 全部通过
```

> **💡 这一步在干什么？**
> 它会检查 6 件事：样式有没有生成对、图标对不对、页面文件齐不齐、
> WXML 有没有错别字、循环变量用没用对、首页逻辑跑不跑得通。
> 全过就说明代码本身没毛病，可以放心推上去。

## 第 2 章：第一步 —— 把代码上传到 GitHub

> **💡 这一章在干什么？**
> GitHub 是「存代码的网盘」。服务器从这里拉代码。
> 你在电脑上改完 → 推上去 → 服务器再拉下来。

### 2.1 看一眼有什么要传

```powershell
cd "e:\9.小程序自己做\02-立了"; & "D:\1、Software\Git\cmd\git.exe" status
```

**成功标志**：看到几行以 `M` 和 `??` 开头的行（`M` = 修改过，`??` = 新增的文件）。

### 2.2 提交（本轮已经提交过了，应该看不到待提交的东西）

如果输出里显示 `working tree clean`，说明**已经提交过了，直接跳到 2.3**。

如果还有待提交的，粘贴：

```powershell
cd "e:\9.小程序自己做\02-立了"; & "D:\1、Software\Git\cmd\git.exe" add -A; & "D:\1、Software\Git\cmd\git.exe" commit -m "第一轮：设计系统底座"
```

**成功标志**：

```
[feature/demo-ui 5fcf175] 第一轮：设计系统底座
 33 files changed, 9182 insertions(+), 232 deletions(-)
```

### 2.3 推送到 GitHub

```powershell
cd "e:\9.小程序自己做\02-立了"; & "D:\1、Software\Git\cmd\git.exe" push -u origin feature/demo-ui
```

**成功标志**：

```
[new branch]      feature/demo-ui -> feature/demo-ui
branch 'feature/demo-ui' set up to track 'origin/feature/demo-ui'.
```

> **💡 如果报「Authentication failed」**
> 说明 Git 没记住你的 GitHub 密码。执行：
> ```powershell
> cd "e:\9.小程序自己做\02-立了"; & "D:\1、Software\Git\cmd\git.exe" push -u origin feature/demo-ui
> ```
> 弹出窗口要你输入：
> - **Username**：你的 GitHub 用户名
> - **Password**：粘贴 **Personal Access Token**（不是登录密码！）
>
> 没有 token？去 GitHub → 右上角头像 → Settings → Developer settings →
> Personal access tokens → Generate new token，勾 `repo` 和 `workflow`，生成后复制。
> **这个 token 只显示一次，复制下来存好。**

### 2.4 确认推上去了

打开浏览器，访问：

```
https://github.com/你的用户名/你的仓库名/branches
```

**成功标志**：分支列表里能看到 `feature/demo-ui` 和 `main`。

## 第 3 章：第二步 —— 更新服务器

> **💡 这一章在干什么？**
> 服务器上跑着后端代码。本轮后端改了一个文件，要让服务器上的代码也更新。

### 3.1 打开 FinalShell，连上服务器

双击桌面上的 FinalShell 图标 → 双击你之前存的那个服务器连接 → 右边出现黑色的命令行区域。

### 3.2 进入代码目录

```bash
cd /var/www/kuile
```

> **💡 如果这行报错「No such file or directory」**
> 说明你的代码不在这个路径。先找一下：
> ```bash
> ls /var/www/
> ```
> 看哪个目录里有 `正式上线版` 这个文件夹，cd 进去。

**成功标志**：提示符变了，没有红色报错。

### 3.3 拉取新代码

```bash
git fetch origin
git checkout feature/demo-ui
git pull origin feature/demo-ui
```

**成功标志**：

```
Already up to date.
```
或者
```
Updating 5fcf175..xxxxxxx
Fast-forward
 33 files changed, 9182 insertions(+), 232 deletions(-)
```

### 3.4 重启后端服务

```bash
pm2 restart kuile-api
```

**成功标志**：

```
[PM2] Applying action restartProcessId on app [kuile-api]
[PM2] kuile-api ✓
```

### 3.5 检查服务是不是活的

```bash
curl https://kuile.banshengcomp.com/api/health
```

**成功标志**：返回一段 JSON，里面有 `"code":0`。

> **💡 如果返回 `502` 或连不上**
> 看日志：
> ```bash
> pm2 logs kuile-api --lines 30
> ```
> 把输出截图给我。

### 4.1 打开微信开发者工具

开始菜单搜「微信开发者工具」→ 打开 → 双击「亏了」项目。

选「从本地重新编译」。

## 第 5 章：出错了怎么办

### 5.1 开发者工具报「编译错误」

先看错误信息里的**文件名和行号**，最常见的三种：

| 错误信息 | 原因 | 怎么修 |
|---|---|---|
| `Component is not found` | 组件没注册 | 检查 `app.json` 的 `usingComponents` |
| `Failed to load resource` | 服务器连不上 | 检查服务器服务是否在跑（第 3.4 步） |
| `{{xxx}} is not defined` | 数据字段名写错 | 用 `node tools/verify.js` 查 |

### 5.2 页面显示一片空白，但没报错

大概率是**循环变量用错了**。跑一下：

```powershell
cd "e:\9.小程序自己做\02-立了"; node tools/check-loops.js
```

### 5.3 颜色没变，还是绿色

大概率是**没重新编译**。按 **Ctrl + B**，或者菜单「工具 → 重新编译」。

还不行就：开发者工具 → 右上角「详情」→ 拉到底 → 点「**清缓存**」→「清除全部缓存」→ 再编译。

### 5.4 服务器更新后接口报错

```bash
pm2 logs kuile-api --lines 50
```

把日志贴给我。

### 5.5 万一改坏了，想回到原来的样子

本轮代码在**独立分支**上，`main` 还是好的。回退方法：

```powershell
cd "e:\9.小程序自己做\02-立了"; & "D:\1、Software\Git\cmd\git.exe" checkout main
```

这样本地就回到老版本了。服务器上也是：

```bash
cd /var/www/kuile
git checkout main
git pull origin main
pm2 restart kuile-api
```

> **💡 小程序前端不受服务器影响**
> 小程序前端是在**开发者工具**里跑的，回退本地的 `main` 分支，
> 重新编译就回到老样子了。
