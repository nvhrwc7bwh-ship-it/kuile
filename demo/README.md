## v3 的三项改造

### 1. 信息降噪 —— 一个主角，其余折叠

上一版的问题：每页平铺十几条数据，视线没有落点，数字长度参差导致视觉混乱。

现在的规则：

| 层级 | 处理方式 |
| --- | --- |
| **主角** | 每页只保留 1 个大数字（如当前体重 68.4kg、失败损失 12 元），字号 36–44px |
| **次级** | 2–3 个关键指标用 `.metrics` 横条平铺，彼此用 1px 分隔线隔开，数字统一 `tabular-nums` |
| **三级及以下** | 全部收进 `.fold` 折叠区，默认收起，点「展开明细」才出现 |

落地的组件：
- `.lead` 主角数字块
- `.hero-nums` 三段式对比（起始 → 现在 → 目标）
- `.metrics` 精选指标条（替代密集四宫格）
- `.mini` 精简信息行
- `.kicker` 关键提示条
- `.fold` 折叠区（`grid-template-rows: 0fr → 1fr` 过渡）

具体改了：首页、广场卡片、Flag 详情、我的、立 Flag、见证席面板、记录卡。

**数字对齐**：所有数字走 `font-variant-numeric: tabular-nums` + `SF Pro Display`，`.row-val` 设 `min-width:34px` 且 `margin-left:auto`，长度不再参差。

### 2. 真实照片头像

`js/avatars.js` 负责，按姓名做 FNV-1a 哈希 → **同一个人永远同一张脸**。

三级降级链：
1. **Unsplash** 真实人像（`?auto=format&fit=crop&crop=faces&w=160&h=160&q=80`）—— 主图源
2. **pravatar.cc** 真实人像 —— 备用
3. **本地矢量人像 SVG** —— 终极兜底，6 种发型 × 6 种肤色 × 眼镜/胡子组合，完全离线可用

加载失败时由 `app.js` 的全局 `error` 捕获（`capture: true`）逐级切换。

### 3. 纯矢量图标

- **零 emoji**：原来 63 处彩色 emoji（💚🍎💬📕📣🔥⚖️🎯🪙…）全部换成单色 line 图标
- 图标集从 27 个扩到 **80+**，全部 `stroke="currentColor"` 单色描边
- `ICON` 改为 **Proxy**，访问时自动注入 `width/height`，避免 SVG 无尺寸时撑成 300×150
- 新增容器级尺寸规则（`.tag svg` / `.row-icon svg` / `.hero .h-badge svg` …），保证全站图标尺寸一致

## 设计系统

| 项 | 规格 |
| --- | --- |
| **主色** | 高饱和亮橙 `#FF6B00` —— 大面积使用也压得住，是本产品的视觉锚点 |
| **强调色** | 朱橙红 `#FF5A3C`（目标/热度）、金橙 `#F59300`（提醒）、亮蓝 `#3B82F6`（信息，唯一冷色平衡）、亮紫 `#8B5CF6`（见证）、正红 `#F0413E`（失败）、亮绿 `#0FBE7E`（达成） |
| **中性** | 暖白底 `#FAF7F4` / 面 `#FFFFFF` / 线 `#F0E8E0` / 字 `#1C1613` → `#B3A79A` 四级 |
| **圆角** | 8 / 12 / 16 / 20 / 26 / 999px 六档 |
| **阴影** | 双轨制：中性暖调 `sh-1~sh-4`（卡片刻意浮起）+ 品牌橙 `sh-brand-sm/md/lg`（只给 Hero、押金卡、悬浮按钮等主角元素）。全部暖棕调 rgba(74,52,32,·)，不是死黑 |
| **字体** | `-apple-system` / PingFang SC；数字用 `SF Pro Display` + `tabular-nums` 对齐 |
| **动效** | `cubic-bezier(.32,.72,0,1)`（iOS 曲线）/ 弹性 `(.34,1.56,.64,1)` |

### 配色逻辑

主色选了**高饱和亮橙 `#FF6B00`**，理由：

1. **够亮才敢大面积用**。这个产品大量使用渐变头图、橙色大按钮、悬浮 FAB，亮橙在这些位置能撑住视觉重量，不会像深色那样显得闷。
2. **所有原本的深色块全部换成亮橙渐变** —— 押金卡、立据凭证、打卡相机区、见证席召集令大字块。原设计用近黑做视觉锚点，现在改用橙白渐变（`#FF9A3D → #FF6B00 → #E85A00`），页面整体从"沉稳专业"转为"明亮有活力"。
3. **浅底衬托**。底色 `#FAF7F4` 接近纯白而非灰，亮橙在浅底上才有跳跃感；纯白卡片（`#FFFFFF`）和暖白底拉开极小差值，靠阴影而非灰度区分层次。

阴影刻意分成两轨，避免"到处都有阴影"的廉价感：

- **中性轨 `sh-lift`** —— 卡片、数据磁贴、选项卡的轻微浮起，一层极淡的双层阴影，只在深浅分层时起作用。
- **品牌轨 `sh-brand`** —— 只给 Hero 头图、押金卡、悬浮操作按钮、记录卡、凭证这五个主角元素。选中态则用 `sh-brand-ring`（3px 低透明度橙晕）代替阴影，暗示"被点亮"而不是"浮起来"。

> 亮橙底上的文字一律用纯白或 `rgba(255,255,255,.72)`，不用灰色 —— 灰字在饱和橙上对比度不足，会发脏。

## 交互设计

### 底部导航（4 Tab）
首页 / 广场 / **通知** / 我的 —— 四个 tab **等宽等分**，「通知」用铃铛图标并带**未读数角标**。

> **⚠️ 2026-11-24（本轮）：底部 Tab 从「首页 / 广场 / 监督 / 我的」改成「首页 / 广场 / **通知** / 我的」**（见 R2.22 ②）。
> —— **为什么换掉「监督」**：
>    ① 原「监督」页只剩「我监督的局」+「我提的异议」，**名不副实**；
>    ② 通知密度本来就高（待判定 / 留言 / 见证席邀约 / 断卡 / 结算 / 异议进展），
>       却只藏在**首页右上角一个铃铛**里 —— 全站最容易被忽略的位置；
>    ③ 每一类通知都是「**错过就要出事**」的事，权重不该输给「监督」。
> —— **原「监督」页的内容各归其位**：
>    「我监督的局」→ **「我的」页功能区**（横向行 + 取消监督 + 二次确认，形态原样保留）
>    「我提的异议」→ **「通知」页**（异议本来就是靠通知推送的）
>    四行假开关 → **整块删除**，承诺说明改为「我的」页法律与安全区的**一行普通文字**
> —— 首页右上角的铃铛**保留**（它带「未读 N」角标，是通知页的快捷入口）。

### 大标题导航（iOS 风格）
顶部 29px 大标题，页面滚动 >34px 时自动缩小为 16.5px 居左小标题，导航栏高度 52→44px 全程缓动。

### 底部弹层（可下拉关闭）
所有规则说明从底部弹出，26px 顶部圆角，带抓手。**手指/鼠标下拉 >90px 关闭**，快速下滑（<260ms 且 >45px）也关闭。遮罩淡入 + 弹层 `translateY` 弹簧动画。

### 页面转场
每页 340ms `pageIn`（上移 8px + 缩放 0.995 → 归位），弹出的详情页用 `pagePop` 弹性缩放。

### 返回
左上角返回键、弹层遮罩点击、说明层内 `✕` 三种方式。Tab 内导航保留各自栈，切回 Tab 恢复上次位置。

### 反馈
所有按钮都有 `:active` 缩放（0.975）、开关有弹性滑动、Toast 从底部 14px 升起。

#### ⚠️ 走查复验：把「看起来能用」变成「真的能用」（2026-11-24 本轮，规则 R2.23）

R2.22 改的是**结构**，这一轮抓的是**实现层的漏洞** —— 结构对了，控件还没通电。
**核心判据：控件要么真的能点，要么就别出现。**

| 位置 | 之前 | 现在 |
|---|---|---|
| **广场筛选抽屉** | 点任意选项**直接报错**（取同组选项写成了「取第一个」却对它调批量方法）；「重画抽屉」的容器选择器根本不存在 | 取全部元素 + 正确容器；选中态 / 结果数量 / 「查看 N 个 Flag」实时更新 |
| **通知两栏** | 「全部」栏有的「待你判定」，「判定·邀请」栏**没有**（两栏数据源不同）；合并时还会**出现两次** | 两栏**双向对齐** + 按编号**去重** |
| **通知上的按钮** | 「去判定 / 查看」**点了什么都不发生**（动作名没有对应处理） | 补 `goVerdict` / `goObjection` / `goGeneric` 三个处理，跳转目标随按钮带 |
| **居中弹窗** | 连点几个「参加」→ **弹窗叠了好几层**，点确认只关最上面一层 | 挂新弹窗前清掉旧的（旧节点**立刻移除**，否则「确认」会点到旧的那层） |
| **通知页「我提的异议」** | 页面上直接印出一个 **`false`** | 条件渲染改成标准的「条件 ? 内容 : 空串」 |
| **`flagTier()`** | 一个空标识让**整页白屏** | 空值兜底成最低档位 |

> **（必读）为什么这类洞最危险** ——
> 它们都属于同一句话：**「控件画出来了，但没通电。」**
> 原型里画一个按钮和让它有反应是**两件事** —— 前者顺手、后者要动逻辑。
> 于是界面看上去**很完整**，评审时看的都是静态界面，没人真的会去点那个筛选框。
> 只有真的一指一个点上去，才知道它是死的。

**① 招募的三个环节各归一处**

| **发现** | 广场「招募中」 | 横条 `.recruit-strip`，一屏能扫 5、6 条 |

|---|---|---|

| 动作按钮 | 底部单独一行 | **整行右侧**（`.notif-acts`） |

**②b 待判定通知的三处修正（2026-11-24 用户口径改）**

| 项 | 之前 | 现在 |
|---|---|---|
| **时间位那一格** | 写「**待判定**」 | **只放真正的时间**（还剩 44 小时 / 还剩 6 小时）；拿不到就整格留空 |
| **判定之后** | 这条通知**直接消失** | **变成「已判定」留在原地**（灰态 `.notif-row.done`、无按钮） |
| **按钮位置** | 在正文行里 → 看着「偏下」 | **提到整行右侧**，跟标题/正文/时间垂直居中 |

- **时间位不写「待判定」** —— 那一格占的是**时间**的位置（旁边写的是「5 小时前」「昨天」）；标题里已经有「待你判定」，重复没信息量
- **判定完不消失** —— 通知是「我做过的 / 要我做的事」的流水，消失 = 用户以为通知丢了；留着变灰 = 看得见「我做完了」
- **已判定的**：留在「全部」栏（灰态）· **不进「判定·邀请」栏**（那一栏是「要我现在做事」的收件箱）· **不算未读**
- **按钮居中** —— `.notif-row` 与 `.notif-line` 都用 `align-items:center`，**不用 `baseline`**（基线对齐会让按钮看着偏下）

**③ 「全部已读」真的清得掉**

- 角标统计的是**现算出来**的通知（待判定 / 见证席邀约），这批数据**每次渲染都重新生成** —— 「已读」没地方存，于是每次重算又变成未读
- 修法：加一份**已读清单** `STATE.notifReadKeys`（按通知的唯一编号记录），现算的通知也要过一遍这份清单
- 点单条通知 = 标记该条已读（行上带 `data-notif-key`）+ 跳转

**④ 立 Flag 三步 + 二次确认**

- `createPay` 页面与路由**已删**；第 3 步改叫「**③ 确认并支付**」，内含押金档位（**一行并排 4-5 个**）+ 失败损失卡（**文字居中**）+ 微信支付 + 打钩确认；**账目汇总整块已删**
- **「押金区间明细」折叠块删除**
- 点「确认支付」弹**二次确认**（`case 'confirmPayAndSubmit'`），文案必须含「**公开生效 / 24 小时 / 不会影响你的目标能不能达成**」三句；未打钩时按钮禁用；**底部小字已删**、**两个按钮等宽居中**

**⑤ 目标详情：日历收起 + 留言轮播**

- **打卡日历默认收起**（`.fold` 不带 `open`），折叠头写摘要「**打卡日历 · 17/30 天 · 断 0 次**」
- **留言改成轮播的流动文字**（`.msg-ticker`）—— 预览真实留言内容，右下角「2/3 ›」既是进度也是入口；**零条留言时退回成「说点什么…」按钮**（`.msg-entry`）

| # | 现象 | 原因 | 修法 |
|---|---|---|---|

>
> —— 所以这里的做法是**纯增加**：原有 8 个场景**一个都没删、没改**，
> 只是**重新分了组**（分组是为了好找），再加 11 个新的。

### 面板结构

| 组 | 场景 |
|---|---|
| **起点** | 新用户 · 游客 |
| **我的 Flag** | 筹备期 · 召集令已发 · +1 个 Flag · **昨天漏打卡** · **补卡超窗** · **断卡** · **已结算** · **押金被扣** |
| **我的互动** | +监督 · **+关注** · **+待回声** · **+异议** · +通知 |
| **见证席** | +完整监督 · **+互动达标** · **已在候选池** · +见证席 · **判定被驳回** |
| **全部** | 老用户 |

分组顺序 = **用户生命周期**的顺序（新手 → 有 Flag → 有互动 → 有麻烦 → 资深），
从上点到下面就是一个用户从注册到成熟的全过程。

面板正文区**可滚动**（`.dp-body`），标题与统计条固定 —— 19 个场景不会糊成一片。

### 新增的 11 个场景为什么是这些

判据：**用户在真实使用中一定会遇到，但以前造不出来**（缺对应的状态字段）。

| 场景 | 造的什么状态 | 落在哪 |
|---|---|---|
| **昨天漏打卡** | `missedOn` + 12 小时补卡窗口（真在走） | 首页补卡提醒卡（带补卡按钮 + 倒计时） |
| **补卡超窗** | 补卡窗口已关 + 已记一次断卡 | 目标详情页「断卡情况」显示 **已断 1 / 3** |
| **断卡** | `status='broken'` + 连续天数归零 + 信用分 -5 | 目标详情页（**不再有横幅** —— 提醒在首页） |
| **已结算** | `status='success'` + 押金全额退回 | 首页归空态（**不再有卡片**） |
| **押金被扣** | `status='failed'` + `f.appeal`（审核中）+ 4 步进度条 | 目标详情页横幅 / 客服申诉页 |
| **已结算的失败** | `status='failed'`（无 appeal） | 目标详情页横幅 —— **只说扣了多少钱，不给申诉入口** |
| **+异议** | `STATE.objections[]` —— 2/3 票，等待转人工 | 监督页「我提的异议」/ 围观者详情页横幅 / 异议页 |
| **判定被驳回** | `verdictTask.rejected` + 驳回原因 | 见证席面板横幅（红） |
| **+待回声** | `f.msgs` 里 2 条未回复的留言 | 首页「N 条留言等你回一句」 |
| **已在候选池** | `inPool = true` + `poolApplied` | 见证席候选池 |
| **+互动达标** | `STATE.interactions = 10`（成为见证席的门槛） | 见证席申请小框（可申请） |
| **召集令已发** | 3 位报名者待处理（1 位已接受） | 发起成功页 |
| **+关注** | `STATE.following` 有 3 人 | 我关注的人 |
| **游客** | `loggedIn = false` + 无任何 Flag | 游客态全站 |

### 两个注入器专用的小工具

```js
myRunningFlag()   // 取「正在跑的那一局」（种子里还有一局已取消的旧局）
focusMyFlag(f)    // 把 f 挪到 STATE.myFlags 最前面
```

> **⚠️ 为什么需要它们** —— 种子里有两局（`f_new_1` 在跑、`f_new_2` 是已取消的旧局），
> 而 `addMyFlag` 是 `unshift`，所以 `STATE.myFlags[0]` 是**那局旧的**。
> 注入器改完 `status` 之后，`myMainFlag()` 的「running[0] || myFlags[0]」
> 也会落到别的局上 —— 于是首页、详情页展示的就不是注入器改的那一局了。
> `focusMyFlag()` 把它挪到最前面，全站就都指向它。

### 打卡照片与生活照（真人素材）

`assets/checkin/ck01.jpg` … `ck12.jpg`（**800×800 方版**）+ `assets/life/lf01.jpg` … `lf12.jpg`（**600×800 竖版**）——
**全部是真实人物 / 真实场景照片**（Unsplash 高质量素材，渐进式 JPEG quality 82，24 张合计约 **1.85 MB**）。

生成脚本在 **`工具/_gen_photos_real.py`**。

```
python ../工具/_gen_photos_real.py
```

> **（2026-11-23 变更）为什么从卡通换成真人** ——
> 这个产品的**全部可信度**建立在「这是真的照片」上。**打卡照片是物证** —— 它之所以能当证据，
> 是因为它是**一个人在某个时间某个地点真实拍下的东西**。一张卡通插画放在打卡记录里**证明不了任何事**，
> 反而暴露了「这只是个 demo」。广场上每一张卡片都应该看起来像**某个真实的人正在真实地做一件真实的事**。
>
> **（边界）只换素材，不改逻辑** —— `photoFor(day, offset)` / `lifePhotoFor(...)` 的**函数签名、取值逻辑、
> 回落链**（补充照 → 打卡照）全部不变，只是底层文件从 `.png` 换成了 `.jpg`。
> `_verify_photos.js` 的魔数校验同步改成 **JPEG `FF D8`**。
>
> **（边界）原来的两个卡通脚本保留** —— `_gen_photos.py` / `_gen_life_photos.py` 留着备查（需要重绘占位图时用），
> 但**现行素材一律走 `_gen_photos_real.py`**。
>
> 12 张素材按 `day` 序号**稳定取用**（`photoFor(day, offset)`）—— 同一天永远同一张，不会每次渲染跳动。
