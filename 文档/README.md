## 四份主文档的分工

```
需求规格.md          →  写代码时查这里    （规则：能做什么 / 不能做什么 / 参数取值）
设计说明.md          →  理解取舍时查这里  （为什么这么设计 / 为什么不那么设计）
页面布局与交互规格.md →  做样式时查这里    （界面怎么摆：布局 / 配色 / 字号 / 组件）
上线清单.md          →  上线前查这里      （逐条核对）
```

**三条硬规矩**：

1. **规则只在《需求规格》里定义一次** —— 其它文档引用它，不复述它。
2. **布局只在《页面布局与交互规格》里定义一次** —— 规则文档提到界面时只说「界面称呼 + 规则」，不带像素、不带类名。
3. **改稿日志全在《想法演进.md》** —— 主文档只留「当前结论」，不留「几号改的、改前是什么」。

## 与 docx 的关系

```
文档/*.md  ──( 工具/_md2docx.py 等 )──>  交付物/*.docx
```

**只改这里的 md，然后重新生成 docx。** docx 在 `../交付物/`，那是产物区，不要直接编辑。

改完跑一次校验：

```powershell
cd ../工具
python check_docs.py              # md ↔ docx 是否一致（标题数 / 表格数 / 围栏配对）
python check_refs.py              # 全文引用完整性
```
