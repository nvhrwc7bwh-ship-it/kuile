# 问题与坑

记录开发与运营中踩到的坑、报错、解决办法。

---

## 待验证的坑（还没踩，先记着）

### 平台 / 审核类

- **微信小程序类目**：减肥属"健康 / 运动"还是"工具"？个人主体能否发布带"目标承诺"功能的小程序？可能要求"健康管理"资质 → 上线前先查类目文档
- **`mediaCheckAsync` 对人体自拍（减肥场景）误判率** → 需保留人工复核通道（官方也建议不要完全依赖 AI）
- **体重 / 围度属敏感个人信息** → 隐私政策需单独说明 + 采集前单独同意（不是勾选框里一句话）
- **微信不提供小程序通用"预授权冻结"** → v1 不做现金，但如果未来上钱，用户的钱要先真的进平台账户，体验解释要提前想清楚
- **平台代发给个人的个税代扣代缴义务** → 若 v2 做赢家分配，平台是法定扣缴义务人（详见 `合规红线.md` W1.2.2）

### 机制 / 运营类

- **⚠️ 见证席机制简化后的新风险：档位定死 = 人不来就吃亏，但用户可能不理解** → 发起页必须明示「档位按**已接受**人数定，24 小时内还能继续邀人」；发起成功页显示「已占 N/10 · 待接受 M · 已接受 K」。**需观察**用户是否理解「待接受的邀约不计入档位」
- **⚠️ 有效档位只降不升，会不会让用户觉得「一次没点就亏了」** → 降档只降**这个 Flag 的**信用分系数与背书，押金完全不动，且**不跨 Flag 累积**（下一个局照常重新定档）。**需验证**用户对「本局降档」的接受度 —— 若实测反馈压力过大，可考虑把「降档」改为「按节点取最低值但不锁死」
- **⚠️ 见证门槛 `min(应到, max(2, ceil(应到×50%)))` 的 50% 是不是太高** → 5 人应到要 3 人判定、10 人要 5 人。**需观察**冷启动期是否频繁触发降级（降级 = 见证背书不作裁决依据）。若降级率过高，可下调到 40%
- **⚠️ 24 小时筹备期里用户凑不到人怎么办** → 单人也能开局（门槛 min 修掉了「1 人永远降级」）；T0 档 ×0.6 系数照常跑通完整闭环。**需观察**T0 占比，若过高说明 24h 不够
- **⚠️ 邀约 12h 有效期会不会太长，导致坑位被占死** → 12h 让坑位在筹备期中段释放（24h 内实际可邀人数 > 10）。**需观察**发起页「已占 N/10」长期贴顶的比例
- **⚠️ 召集令须在发起后 4 小时内发布，但用户不一定能马上发朋友圈** → 若实测发现 4 小时内发不出去的比例高，可考虑把召集报名窗口从 20h 缩到 16h（给接受期留更多余量）
- **⚠️ 退出的见证席既占应到人数又不判定，等于永久拉低档位** → 这是「只降不升」的必然代价。**刻意取舍**：不接受补位机制（用户明说「找不到人后面就不允许加了」）。**需观察**退出率，若退出率高则档位会被系统性拉低

- **公开失败页的二次伤害**（对减重失败用户的心理打击）→ 靠失败记录卡重定义 + 主动认输 + 续期缓冲
- **围观者的动机从哪来** → 见证等级、社会回报、互为见证、**押金带来的真实 stakes**。**这是 v1 最大的未验证假设**
- **见证席会不会只看不动手** → 贡献分只认"提交有效判定"，但仍需观察实际提交率
- **随机抽检会不会引发反感** → 突然性是它的价值，但频率要克制
- **冷启动：围观者要动力，动力要观众，观众要内容** → 需要种子池人工运营，且广场只放"今日待完成的高风险目标"，让围观者三秒内能判断要不要点进去
- **⚠️ 见证席不足 3 人 → 无法发起 Flag（v1 头号卡点）** → 见证席召集令（公开征集 + 承诺责任 + 定员 3 位）。**这是启动问题不是产品问题**
- **⚠️ 一次性邀约会不会太轻，导致见证席不认真** → 靠三道防线：连带责任（漏报 -8）、判定成立率校准、3 次漏报取消资格
- **⚠️ 监督席"白嫖"会不会太多（只围观不互动）** → 靠存在感可见性（"X 人监督"）+ 结局通知 + 记录卡；且监督席是见证席的供给池（**完整监督 1 次**可申请，见 R5.9）
- **⚠️ 小红书带码图导致用户笔记被限流/封号** → v1 明确不做带码图；只发无码记录卡 + 品牌词引导。详见 `合规红线.md` W5
- **⚠️ 扫码落地页首屏是授权弹窗 → 转化率崩** → 静默登录（openid）先展示「立据」内容，用户点"我要监督"时才引导完善资料。**原则：先给价值，再要授权**
- **AI 判负误判** → 判负必须人工确认 + **24 小时**申辩窗口 + 撤销不留痕
- **见证席刷「作弊」判定骗分** → 配额上限（每月 N 次）+ 成立率 <60% 失去加分效力
- **⚠️ 3 票异议阈值形同虚设** → 旧设计里举报是「1 人触发 AI 抽检」的单人通道，3 票从来不是启动核查的门槛。**已改：举报变见证席专属（1 人转人工），异议变监督席专属（≥3 票转人工），两条通道互不计数**
- **⚠️ AI 把 3 票异议一句话驳回** → **质疑路径一律不经 AI**（见证席举报 / 监督席 3 票 / 24h 窗口内的异议，三者直转人工）。AI 判「合规」是直接结算的，让它先跑就等于把质疑通道关上了
- **⚠️ 人工审核量上升** → 见证席判「作弊」从「走 AI（便宜）」变成「全部走人工」。**刻意取舍**：把「有人认真质疑」交给最可靠的一环；冷启动期见证席只判按周期的 2–4 个节点，量可控。**需观察**冷启动后人工队列是否堆积（**2026-11-19 提醒：节点按周期缩放后 30/90 天各多一个节点，人工量再涨 33%**）
- **⚠️ 24h 异议窗口可能变成无限循环** → 窗口内提异议 → 转人工重审 → **重审结论即终局**，不再开第二个窗口。**需验证**用户是否接受「只有一次复议机会」
- **⚠️ 监督席对审核结论提异议是否也需 3 票** → **需 3 票**（否则单人可推翻已完成的审核，阈值守不住）。**若实测发现单人在窗口内提异议就能重审，需补规则**

### 围观飞轮类（2026-11-15 新增）

- **⚠️ 空广场 = 死** → 必须有可围观的内容。**官方示范 Flag × 5 个提前 30 天启动**（真人身份，不用官方标签），否则机制全是空的
- **⚠️ 围观者只围观不互动（白嫖）** → "监督数"数字可见 + 匿名互动 + 围观者自己的记录卡（三视角之一）
- **⚠️ 熟人场景围观尴尬导致流失** → **互动匿名但计数**（只见数字不见人）+ 预设短语（非自由评论）。**见证席则相反，必须实名**（连带责任需责任确定）
- **⚠️ 失败静默 → 追剧断在半路 → 飞轮卡死** → **未达标照样出图**（"围观者要的是结局"，失败无结局 = 产品信用问题）
- **⚠️ 断卡通知被当成骚扰** → **只推剧情节点，不推日常体重变化**。断卡/判负/结算/临近结束 四类
- **⚠️ 广场信息流刷起来像表单** → 卡片必须有内容感（前后对比 + 头像墙 + 金句）；**订阅流优先于广场**（打开动机强）
- **⚠️ 站外流量落到广场首页 = 白白浪费** → 必须落到**某个具体 Flag 的页面**（有内容、能代入），且该页要同时给"订阅"和"我也可以立"两个 CTA
- **⚠️ 影子目标做成排行榜** → 立刻变锦标赛 → 涉赌质疑。只做**个人参照**，无排名、无资金对抗
- **⚠️ 官方示范 Flag 被识破是广告 → 反噬信任** → 用真人、普通用户身份、不加官方标签、不做官方转发

### 载体与推送类（2026-11-16 新增）

- **⚠️⚠️ 小程序拿不到长期订阅消息（决定性约束）** → 官方明确：长期订阅**仅向政务民生、医疗、交通、金融、教育等二级类目开放**，我们的类目拿不到，**无模板即不支持、不能自定义**。只能用一次性订阅（每次弹窗授权才能发一条）→ **我们的断卡/判负/结算/每日提醒全部不可行** → **这是「App 为主」的核心理由**
- **⚠️ 一次性订阅会让推送体验崩坏** → 用户要为一条"结束通知"重新点授权 → 必须在**打卡成功页 / 订阅页 / 见证席接受邀约页**提前引导授权攒额度
- **⚠️ 服务号模板消息需先关注公众号** → 多一层漏斗；官方提示"这种容易风控"，**不做群发性质内容**
- **⚠️⚠️ "能上 iOS 和安卓" ≠ "推送能用"** → 国内 Android 要接 华为 HMS / 小米 MiPush / OPPO / vivo / 魅族 + FCM 共 **4–5 个通道** → **用第三方聚合服务**（个推/极光/友盟）；降级到 App 内轮询 + 首页红点；**必须埋到达率与点击率**
- **⚠️ App 端内容安全要自建** → **App 的推送与分享不走微信审核**，`mediaCheckAsync` 覆盖不到 → 用户昵称/体重/物证必须自己过滤（图片鉴黄 + 文本审核 + 人工兜底）
- **⚠️ iOS 收押金只能走虚拟支付** → Apple 抽 **12%+**，独立商户号、道具配置、T+3 结算，**iOS 还要等 Apple 45–60 天** → 用**高价档**方案（用户看到「iOS 押金 400 元」，与费率无关，无透明度问题），**不要用费率上浮**（会被投诉）
- **⚠️ 后端绑了微信云开发 = App 端走不通** → 云开发对非微信客户端支持有限 → schema 从第一天就按双端设计（用户体系/认证/API 边界不绑微信）
- **⚠️ 跨端框架在小程序端微信能力支持参差** → `onShareTimeline` / 小程序码 / 静默登录 / 订阅消息 —— **裂变链路是生命线，不能冒险** → 小程序端坚持原生
- **⚠️ 双端并行 = 两倍开发 + 两套审核 + 两倍 bug** → 改「App 为主 + 小程序作壳」，小程序最终态只做 3 件事（展示立据+订阅 / 极简打卡 / 引导装 App）
- **⚠️ M2 阶段 App 未开发，小程序必须独跑全功能** → 页面清单的「端」列是 **M4 目标态**，别当成 M2 的裁剪清单
- **⚠️ App 获客不能靠买量** → 路径是「微信裂变 → 小程序 → 装 App」，且只引导**已经立了 Flag 的人**装（他们不需要被获客，只需要被提醒去装）
- **⚠️ 厂商消息分类配错 → 推送收不到** → **必须按厂商规则配置「系统消息 / 重要消息」分类**；**华为/荣耀必须配证书指纹**；**OPPO/vivo 有消息分类新规**；厂商资源文件名不能改（改了集成失败）；每日推送总量受厂商限制（按订阅数动态计算）
- **⚠️ FCM 在国内多数机型不可靠** → 只能作海外或补充通道，国内必须靠厂商通道

### 留言板类（2026-11-16 新增）

- **⚠️⚠️「无评论」被推翻，但「公开评论楼」仍然绝对不做** → 留言板。
  **⚠️ 2026-11-23 口径反转**：留言改为**公开可见** —— 但**防网暴的结构性防线从「不公开」换成了「不做评论楼 + 不做回复链 + 点赞独立计数 + 审核举报禁言」**（见 `需求规格.md` R14.4）
- **⚠️ 留言变人身攻击**（"骗子""滚"）→ 内容安全审核 + 举报 + 禁言；**目标人可一键删除**；但**匿名让人敢写，也让攻击者以为没后果** → **必须靠审核兜住，不能靠匿名兜**
- **⚠️ 熟人场景留言尴尬** → **半匿名**（"一位监督席"）+ 预设短语兜底；见证席实名（有法律责任，其留言是"证词"不是"评论"）
- **⚠️ 留言演化成攀比榜** → 2026-11-23 留言**已公开可见**，所以防线改成：**绝不做留言数榜单** + **不产生 Flag 级留言总数** + **每条留言点赞独立计数**（不跟 Flag 的任何总数挂钩）
- **⚠️ 留言刷屏** → 2026-11-23 用户口径：**留言不限次数**。所以刷屏防线改成**审核 + 举报 + 禁言 + 一键删除**（配额挡不住刷屏，一个人可以分分钟发 10 条）+ ≤60 字
- **⚠️ 见证席实名留言可能被针对** → 见证席本身就有连带责任压力，不额外加重；但**必须防止"因为你是见证席所以专门针对你"** → 举报 + 禁言

### 见证席缺席类（2026-11-16 新增）

- **⚠️⚠️ 硬门槛检查的是"名单长度"，但真正起作用的是"实际响应率"** —— 因为「收到节点任务时才知情」，**填 5 个假名字就能过门槛**。**硬门槛拦不住任何人，只拦住诚实的人** → 改为**强度分级 T0–T3，按实际响应定档**
- **⚠️ 冷启动期硬门槛是致命的** —— 种子 200–500 人里绝大多数用户不会有 3 个朋友在平台上 → **硬门槛 = 产品对绝大多数新用户不可用** → 0 位见证席也能发起（T0）
- **⚠️ 见证席不能中途加入 → "先开始、以后再找人"的路被堵死** → 放开，但**必须用「明确生效日期」界定责任**（记录卡标注加入日、责任从加入日算、押金不追溯）
- **⚠️「没点」和「判通过」混为一谈** → 判定状态必须拆开：**通过 / 存疑 / 作弊 / 未响应**（表态的三种 vs 没表态）。「不想判断」不要单开一档 —— 用**拒绝**（接受前，每局 1 次不扣分）和**退出**（接受后，不追溯扣分）两条出口；「存疑」已覆盖"看不懂物证/不认可这个 Flag"的场景且待遇更好（✅ 计入见证门槛）
- **⚠️ 惩罚梯度不能反过来** —— **把"没点"罚得比"点错"重，是在惩罚诚实的人**。正确梯度：判错（-8）> 长期失联（累计 3 次）> 一次没看手机（0 分）
- **⚠️ 连带责任不该扣"没打开 App 的人"** → 分母收窄为**「已判定且判通过者」**，未响应不受连带
- **⚠️⚠️ 不设见证门槛 会开天窗** —— "见证席没反应" = "没人管 = 自动通过" → 见证席、连带责任、存疑抽检**全部作废**。**见证门槛 = max(2, ceil(应到×50%))**，不满足则该节点**降级为「仅平台审核」**
- **⚠️ 见证门槛降级不能惩罚发起人** —— 他已交押金、承担失败扣收，不该因"朋友没看手机"被追加惩罚 → **降级只影响见证背书**
- **⚠️ 召集令截止时间 10 分钟是明显 bug** —— 10 分钟是给发起人反悔用的，不该是别人报名的时限；**朋友圈召集需要真实传播时间** → 改 48 小时，与节点预告窗口对齐
- **⚠️ 定员写死"3 位"与强度分级对不上** → 改为按目标强度（T1=2 / T2=4 / T3=5）
- **⭐ 反过来的一致性红利**：钱只跟**你的行为**（可控）有关，见证背书跟**别人的反应**（不可控）有关 → 这条线让「不是运气，是可控行为」的论证更强，也解释了为什么见证席未响应不扣分

### 见证席通道类（2026-11-17 新增）

- **⚠️⚠️ "监督满 3 次"在原文里根本没有定义** —— 没人说清"一次监督"是什么。是点了"我看着"？还是发过一条留言？按最松读法，**订阅 3 个 14 天 Flag 就能换到见证席资格** → 补上极简定义（见 `需求规格.md` R5.9.3）：**已出结局 + 至少陪了 3 天 + 期间互动过一次**，同一发起人只计 1 次
- **⚠️⚠️ 门槛不能证明判断力，只能证明"不是空号"** —— 这必须写清楚，否则会误以为"有门槛 = 见证席靠谱"。**判断力靠连带责任机器事后校准**（误报 -15 / 漏报 -8 / 累计 3 次漏报取消资格）
- **⚠️⚠️ 删掉担保人和平台审核后，唯一的防线是"候选池公开 + 发起人自己挑"** —— 如果候选池不做展示字段（信用分 / 成立率 / 已见证次数 / 关联度）、发起人页不给挑选入口，**那门槛就是唯一防线，而它挡不住任何认真作恶的人**。**这两件事必须捆绑做，不能拆**
- **⚠️ 候选池不能做成"自动成为见证席"** —— 那样背书被稀释（记录卡头像墙全是陌生人）、社会压力消失、发起人失去选择权，4.1 的"社交属性：强（真实关系）"直接崩掉 → **候选池是供给侧加速器，不是准入替代品**。两条通道终点一致：都要发起人接受或公开召集录取
- **⚠️ 通道 A（邀请制）必须零门槛** —— 要求"被邀请者先证明自己"等于把冷启动用户锁死在 T0（种子 200–500 人里绝大多数不会有 3 个朋友在平台上）。**关系信任本身就是筛选**
- **⚠️ 比例型门槛（如"陪够周期 50%"）用户算不明白、开发也难做** → 改用**固定 3 天**这个绝对数字，一句话能说完，一个时间戳比较就能实现
- **⚠️ 担保人机制已取消** —— 它的作用是"确认这个人不会乱判"，但这件事已由连带责任机器 + 候选池公开 + 发起人自选承担。**保留它只会把普通用户变成见证席的难度提上去，而不提高背书质量**
- **⚠️ 19.5 转化阶梯 L4 写的是"3 次节点判定"，是循环论证** —— 节点判定是见证席的义务，得先当上见证席才能做 → 改为"完整监督 1 次"

### 押金类（2026-11-16，2026-11-18 全面重构）

- **⚠️⚠️⚠️ 押金只有上限、没有下限 → 90 天大目标可以只押 30 元** —— 押注严肃性归零，**周期长度失去全部金钱意义**，用户会理性地全部选 7 天。**解法：押金必须是区间制** —— 每个周期有下限（7 天 100 / 14 天 200 / 30 天 500 / 90 天 1000），信用等级决定上限（200/500/1000/2000/5000）
- **⚠️⚠️ 押金上限跟见证席强度挂钩 → 支付死锁** —— 强度按**实际响应**算 → 用户填 5 个名字没人回应时只能按 T0 算押金；而押金越高见证席越可能接受（「押 5000 的局值得担责」）→ **押金等见证席、见证席等押金**。另外强度上限与周期下限是两个独立量，一旦冲突就出现「这个组合无解」的空洞。**解法：押金只由「周期」与「信用」决定，强度解耦**（强度只管信用系数 / 背书 / 广场权重）
- **⚠️⚠️ 费率如果不随周期抬升 → 长周期反而扣得少** —— 90 天费率低于 30 天 → 周期越长损失越小 → **周期倒挂**。**解法：费率只跟信用有关（跟周期无关）→ 周期差异只通过下限体现 → 下限严格递增 → 乘一个常数，单调性保持**。这样还省掉了「周期费率下限」这条补丁规则
- **⚠️⚠️ 单档格 = 用户没有选择权** —— 旧表里「受限 14 天」「普通 30 天」各只有**一个**可选档位。**解法：可立周期判定用**严格小于**（`周期下限 < 信用上限`）→ 每个信用在每个可立周期上至少 2 个档位**。而且「信用 < 80 不能立 90 天」这条硬规则可以整个删掉 —— 它就是公式的必然推论
- **⚠️⚠️ 认输打折在费率上调后变成漏洞** —— 认输阶梯的前提是「失败扣得比认输多」，但费率上调到 20–40% 后，**失败扣 20%、认输只扣 5% → 主动认输比"努力了但没做到"便宜 4 倍**，这是在鼓励中途放弃。**解法：删除认输功能**（`需求规格.md` R7 已删）。**代价**：90 天投了 85 天放弃要扣 20% —— 接受这个代价，换取"失败代价不因中途放弃而变便宜"
- **⚠️ 把"押金金额"和"押金上限"混成一件事 → 设计出错** → 必须拆成三个独立维度：**金额**（周期区间）/ **上限**（信用等级）/ **费率**（信用等级）。混了会出现"信用越高能押越少"的反直觉结果
- **⚠️ 信用高 = 能玩更大的赌局 → 会不会滑坡成赌博？** → 不会，因为三条约束同时成立：① **信用分只决定"输多少钱"，不决定"输了多难受"**（连带责任/公开留痕/进度清零对所有人同等重）② **大 Flag 的信用回报更大**（+35 vs +15，见 R8.1）→ 是正期望 ③ **大 Flag 失败扣更多信用分**（-20 vs -10）
- **⚠️ "更大 Flag"变成规模竞赛 → 失败者聚集地** → **五重约束**：押金上限随信用 / **押金下限随周期递增** / 健康门槛 / 大 Flag 失败扣更多分 / **见证席强度影响信用分系数**
  - **⚠️ 强度影响信用分系数（成功与失败同步打折）是公平性关键** —— 否则"没人看着"反而更划算，T0 成了理性选择，见证席机制就空了
- **⚠️ 新人死循环** → 没信用记录 → 没押金额度 → 立不起 Flag → 无法积累信用 → 永远起不来。**解法：第一个 Flag 免费（0 元）**
  - **⚠️ 免费只覆盖 7 天不够** —— 可立周期改为公式推导后，普通信用只能立 7/14 天 → 14 天免费一局 +10 分直接跨过良好（70）门槛 → **新用户两局解锁 30 天**。免费应覆盖 **7 天 + 14 天**
- **⚠️ 押金归集到平台一般账户 → 长租公寓判例** → 逐用户独立记账、专款专用、**平台不得从押金中盈利**（否则构成"第三方从赌局获利"）
- **⚠️ "全有全无"扣款条款无效** → 扣除须**以实际损失为标准**；**达标必须 100% 全额退还**（无损失无理由扣款违法）
- **⚠️ 押金协议缺一项即违法**（消保条例第 20 条 / 电商法第 21 条）→ 退还条件 / 退还流程 / 处理时限 / **扣除标准与计算方式** / 不可扣除情形 / 申诉渠道
- **⚠️ 押金 ≠ 会员费** → 会员费是服务对价（可留），押金是履约担保（**必须能全额退回**），**不能混在同一个支付按钮里**
- **⚠️ 失败押金分给见证席 = 押金瓜分** → 与脸疼的围观币瓜分挑战金**结构同构**，命中打卡诈骗专项治理。**绝对不做**
- **⚠️ 开放时机** → 必须等**推送上线 + 退款流程压测通过 + 客服 SLA 就位**。建议先只开"达标全退"形态，扣收比例从 **20%/25%**（优秀 / 卓越两档）起步

### 信用分取整类（2026-11-18 新增）

- **⚠️⚠️ 唯一一个非 5 倍数的基础分，会长出一条永久的例外规则** —— 早期「7 天失败 -3」是全表**唯一**非 5 倍数（3×0.6 = 1.8、3×0.8 = 2.4），为了它不得不写一条「7 天 Flag 一律按整数结算、不打折」的特例，散落在 R8.3 / R8.4 / D8.7 / demo 四处。**解法：把 7 天失败改成 -5**（与 14 天一致）→ 5×0.6=3、5×0.8=4 均为整数 → **例外规则整条删除，取整论证变成完全统一**
- **⚠️ 顺带消掉一个隐性优势** —— 原来 7 天失败只扣 -3、14 天扣 -5，但成功分都是 +5 → **只看信用分，7 天局反而更划算**。改 -5 后两者对齐，短周期的优势只在押金维度体现（100–500 vs 200–1000），两个维度方向一致
- **⚠️ 教训：设计分值时先问"这个数会让乘法闭合吗"** —— 不要事后补取整规则，**要让乘法天然闭合**。一个非 5 倍数的基数 = 一条例外规则 + 四处同步维护

### 信用分体系类（2026-11-17 新增）

- **⚠️ 分值必须落在 60–100 的量表内** → 早期设计按"天数"给分（90 天 = +100），**初始 60 + 一次 90 天就爆表**。信用分是 0–100 的量表，**只有 40 分空间**，所有加分必须按"离 100 还有多远"设计。**教训：设计分值前先确认量表边界**
- **⚠️ 系数 × 基数必须天然得整数** → 早期用 ×0.5，配 5 分基数直接算出 **2.5 分**。**解法：基数全取 5 的倍数 + 系数只用 0.6 / 0.8 / 1.0** → 5×0.6=3、10×0.8=8、35×0.8=28，**全部整数，一条取整规则都不用写**。**教训：不要事后取整，要让乘法天然闭合**
- **⚠️ 信用分下限必须存在，否则一次失败把新人打死** → 新用户立 30 天失败 -10 → 50 分；若下限是 60，就要连做两个 30 天才能回来 = **冷启动惩罚**，最容易流失的场景。**解法：45 分地板**（扣到 45 即止）+ 受限档**只锁规模不锁发起**（还能立 7/14 天自救）
- **⚠️ 受限档不能锁"完全不能发起"** → 用户没有自救路径 = 彻底出局，只能弃用。**锁规模（只能立 7/14 天 + 押金上限 30 元）才是真惩罚**
- **⚠️ 分数只在结局结算时动一次 = 新手期反馈断层** → 新用户第 1 天立 Flag，然后 14 天没动静，**第一次"大奖"要等 90 天**。**解法：分段到账**（14 天第 7 天 +5 / 结束 +5；30 天第 7 天 +5 / 结束 +10；90 天第 7 天 +5、第 30 天 +10 / 结束 +20）。**长线 Flag 从第一天起就在回报**
- **⚠️ 中期到账必须有前提，否则白送** → 三个前提：**打卡完整 + 未主动认输 + 未被判负**。**断卡 → 这笔不给，但已给的保留**（断卡是状态，不是罪 —— 他第 7 天确实守住了）
- **⚠️ 记录卡只在结束结算时出，中期只发分数** → 中期出图会让"未达标"变成半个结局，**提前消费仪式感**，且失败记录卡会提前泄露
- **⚠️ 见证席按节点计分 = 可被并发放大** → 一次 Flag 3 个节点各 +2，若无限制，同时被邀 20 个 7 天 Flag 的见证席 → **7 天 +120 分直接爆表**。**解法两条：① 每周见证加分上限 +6 ② 同时最多 3 个见证任务**（**2026-11-19 更新**：节点数改为按周期缩放，30/90 天档 4 个节点 → 上限提到 **+8**，否则 30 天局一次就顶格、规则自相矛盾）
- **⚠️ "同时最多 N 个"限的是并发不是速率** → Flag 一结算名额立刻释放，所以它**防不住刷分，只防住用户被淹没**（别错过 48h 窗口 → 漏报）。**真正防刷的是周上限 +「错判一次 -8 抹掉 4 次收益」的赔率**
- **⚠️ 周上限要等于"一个 Flag 的量"** → 上限 +8 = 完整陪一个 30 / 90 天 Flag 的收益。**用户心智只有一句话：「一周当见证席，顶格收益 = 一个长周期 Flag」**。且上限要显式展示成进度条「本周 +2 / +8」—— **让上限成为期待感而不是限制感**
  - **⚠️ 2026-11-19 这条心智已改写** —— 陪到底收益改为按周期递增（7 天 +4 / 14 天 +6 / 30 天 +8 / 90 天 +8），周上限提到 +8 后，新心智句是：「**一周当见证席，顶格收益 = 完整陪一个 30 / 90 天 Flag**」
- **⚠️ 见证席与监督席的收益不能同档** → 监督席异议成立只给 **+1**（象征性认可），因为"复核坐实作弊"是极小概率事件，**+1 在事实上等同于荣誉标记，不构成刷分路径**；不成立 **-8** 与见证席误报同档
- **⚠️ 强度系数不应作用于见证席分值** → 系数衡量"你的 Flag 有多少人看着"，见证席分值衡量"你作为见证席干得好不好"，**两件事不该相乘**。否则会出现"当见证席时自己 Flag 无人看 → 见证分也被打折"的荒谬逻辑
- **⚠️ 拆 Flag 略占优是已知取舍，刻意不修** → 90 天拆成 3 个 30 天 = +45 > 单个 90 天 +35。**产品本质是"用户为自己努力"，拆不拆都是真实坚持量**。若用户反馈，最省事修法是把 90 天改成 +45
- **⚠️ 信用分封顶后必须有替代成长线** → 100 分封顶后，一批高粘性用户会失去目标。**三条替代线：押金上限 / 见证席特权等级 / 记录卡背书强度**
- **⚠️⚠️ "14 天 +20 / 90 天 +40"允许 2 次 14 天刷到 100** → 短周期单日回报反而高于长周期（14 天 1.43 分/天 vs 90 天 0.44 分/天），**用户的最优策略是刷短的**。**解法：把分差拉开到"周期越长、单位时间回报越高"**（现为 7 天 +5 / 14 天 +10 / 30 天 +15 / 90 天 +35）
- **⚠️⚠️ 复杂的数学模型（指数衰减 / 幂律 D^1.3 / 尺度相关费率）会让用户放弃理解信用分** —— 信用分的功能是"我做对了就涨、做错了就跌"，**一旦需要计算，它就只剩数字没有意义**。**解法：全表固定分值 + 唯一一个乘法（强度系数 0.6/0.8/1.0）+ 基数全取 5 的倍数** → 算出来必然是整数
- **⚠️ 规则表里出现"生效条件"比数值本身更重要** —— 规则表里明写「**没有**被他人见证」「**没有**打卡每天 +N」—— 少写一条，用户就会以为漏了

### 见证节点类（2026-11-19 新增 · 节点按周期缩放）

- **⚠️ 见证次数与周期不匹配 = 责任与监督频率脱钩** → 旧设计所有周期一律 2–3 个节点，**90 天档（押金 1000–5000、失败扣 35–40%）和 7 天档一样只判 2–3 次**，而且第 30 天到第 90 天**有 60 天完全无人监督**。**教训：节点验证的是「时点」不是「过程」—— 责任规模（押金）涨了，监督频率必须跟着涨**
- **⚠️ 节点变多 → 见证席疲劳，后段节点形同虚设** → 90 天用户要判 4 次，第 30/60 天的节点很可能被无视 → **节点数增加了，实际监督密度未必提升**。**解法：节点前推送 + 待办红点配套**，否则只是「多两个摆设节点」。**待验证**
- **⚠️ 人工审核量会再涨 33%** → 30/90 天各多一个节点，而 2026-11-18 刚把「质疑路径」全部改为转人工。**叠乘后冷启动的人工队列可能堆积 —— 上线后优先看队列长度**
- **⚠️ 每周上限提到 +8 后，防刷分强度下降** → 旧设计的用户心智是「一周当见证席，顶格收益就是一个 Flag」，现在 30 天 Flag 本身就值 +8。**防刷强度按周期等比保持；心智话术已改写为「一周当见证席，顶格收益 = 完整陪一个 30 / 90 天 Flag」**
- **⚠️ 新增节点必须区分命名** → 30/90 天档有 4 个节点，若都叫「中期称重」，**记录卡与收益页会出现两条一模一样的条目**，用户会以为系统出错。**解法：第 2 个中期节点叫「中期复核」**
- **⚠️ 不要用「摊薄」来维持陪到底总额不变** → 4 节点摊薄成 +1.5 会**产生碎数**，直接破坏 R8.4「所有基础分都是 5 的倍数、无需取整」的约定。**收益递增（+4/+6/+8/+8）比摊薄更符合「责任匹配」**
- **⚠️ 节点计划必须在发起时算死并写入规则快照** → 否则平台改节点规则会**追溯影响已发起的 Flag**（已提交的判定 / 异议 / 申诉都引用节点序号，序号必须稳定）

### 变更管理类（2026-11-19 新增 · 全面复核的教训）

- **⚠️⚠️ 改了主文件 ≠ 改完了** → 一次重构改 8 个文件约 40 处，人工扫一遍必然漏。**2026-11-19 复核实际查出 4 处漏改**：`info.js` 周上限还写 +6、`pages.js` 抽检加严还写「每节点 1 次」、`合规红线.md` 还写「3 个称重节点」、`设计说明.md` 指向一个**并不存在的待验证项**。**教训：每个数字都要先问「它应该在哪些文件里出现」，再逐一核对 —— 而不是改完主文件就以为完事**
- **⚠️⚠️「待办」没闭环 = 规则改一半、文案改一半** → 上一轮把周上限 +6 → +8，配套的用户心智句当时留了空（「新的心智句待定」），结果 `设计说明.md` 指向一个**并不存在的待验证项**，而 `问题与坑.md` 里那条心智说明还是旧的。**这类漏改不是数字错，肉眼扫数字根本扫不出来 —— 它是「状态」漏了**。**解法：每次改完，把所有「待定 / 待验证 / 待办 / TBD」全搜一遍，要么闭环要么明确标为未决**
- **⚠️ 靠人扫的核对方式不可持续** → 前三轮全靠人工核对 8 个文件，每次都是「改完靠眼睛扫一遍」。**人会疲劳，机器不会**。**解法：把「必须一致」写成可执行断言**（本项目 `_verify_consistency.js`）—— 这正是 R0.6「单一真相源」那条规则的工程化落地（文档层「只在 R8.1 定义」，代码层由脚本守）
- **⚠️ 手写的重复文案迟早会漏** → `pages.js` 里手写的限次文案和 `data.js` 里对应的常量是同一个事实的两份拷贝，改了后者前者不会自动变。**解法：展示层一律读常量，不手写字面量**
